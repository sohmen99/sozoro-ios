## ヒートマップ

**ウェブ版の `refreshHeat` と `<g id="heat">` をそのまま移してあります。**

```
半径   = 22 + crowd * 0.36        （px。図は 16m/px なのでメートルに直す）
色     = 空き=緑 #0E9578 / やや混雑=赤 #C0392F / 混雑=紫 #7B2D8E
段     = 40未満が緑、40〜69が赤、70以上が紫
濃さ   = 0.10 + crowd/100 * 0.34
ぼかし = feGaussianBlur stdDeviation="26"
全体   = mix-blend-mode:multiply, opacity 0.85
```

比で正規化したり、時刻で減衰させたりはしません。**絶対値をそのまま出します。**
深夜に薄くなるのは実際に空いているからで、それが正しい。

**ぼかしを省くと別物になります。**半径 R の一様な円板に σ=26px のガウスをかけると、
小さい丸ほど中心まで薄まる。22px の丸（混雑0）は中心でも 0.30 までしか立たず、
58px の丸（混雑100）は 0.92 立つ。空いている場所が自然に沈むのはこの効きで、
ぼかさずに円を描くと全部が同じ濃さの塊に見えます。

閉じた式にならないので、`HeatProfile` が半径ごとに数値積分して 22 段の断面を作り、
`CGGradient` の色止めに渡しています。半径は 22〜58px の整数しか出てこないので、
一度作れば以後は引くだけです。

```
日曜14時  緑 3 / 赤 9 / 紫 9        ← ウェブ版の README と同じ数
日曜 2時  緑 21 / 赤 0 / 紫 0
```

### プレビュー

`RootViewController.swift` の末尾に**6枚**あります。Canvas（⌥⌘↩）を出すと、
表紙・地図・三択・コンパス・到着・印がそれぞれ出ます。

```swift

```

`WalkStore.preview(stage:)` が上野に立った状態を作るので、**位置情報も実機も要りません。**
プレビューでは `LocationService` を起こさないので、許可も出ません。

`RootViewController.swift` の頭に `import SwiftUI` が入っています。**消さないでください。**

## 羅針盤

盤はウェブ版の 300×300 の図をそのまま起こしたものです。針も `#needle` と同じで、
行き先側だけを矢にして、反対の端は短い重り（線と小さな三角）にしてあります。
先端の短い印と、軸から34の位置の「THIS WAY」も同じ。文字は針について回りますが、
南を向いたとき逆さになるので、回した分は打ち消して立てています。

**縮尺は frame では当てません。**`frame` は bounds・position・transform から
逆算される値なので、すでに縮尺の掛かっている層に代入すると、その分 bounds が
小さく取り直されます。呼ばれるたびに縮むので、残り距離の表示が変わるだけで
盤がずれていきました。bounds と position と縮尺を別々に置いてあります。
明暗を12回切り替えてレイアウトを走らせ、盤の画素が1つも動かないことを見ています。

## 行き先の写真

**58件に実写真が入っています。**出所は Wikimedia Commons、ビルド時に焼き込み。
アプリは一度も取りに行きません。会場の回線が弱くても、Commons が落ちても出ます。

```
python3 tools/photos.py ~/Downloads/sozoro_matched_185.xlsx
→ Resources/photos/*.jpg（480px・4.2MB）と photos.json
```

**採るのはその場所そのものを写したものだけです。**照合表の94件から、次を落として58件：

| 落とした理由 | 件数 |
|---|---|
| 被写体がその場所ではない（別の建物・所蔵品） | 9 |
| 同名の別の寺（本行寺 — 写真は元浅草、行き先は西日暮里） | 1 |
| 表の照合ちがい（筆や — 写真は隣の総持院） | 1 |
| ファイル名に名前が無く、その場所だと確かめられない（長久院） | 1 |

撮影者とライセンスは表のクレジット欄ではなく **Commons API から引いています。**
表の文字列は手で書いたものなので、出典として出すには弱い。

- **三択** … ウェブ版と同じ `blur(11px) saturate(1.25) scale(1.35)`。ぼかしたあとに
  残るのは色と明暗だけなので、正体は伝わりません。写真の無い枚は色の面だけを敷きます。
  **線のアイコンは置きません** — ぼかした写真と線画を並べると、線画が「はずれ」に見えるので
- **到着** … ここで初めてぼかさずに出します。撮影者とライセンスを下に添える

引いた三択のうち写真がつく割合は、**11時40% / 14時40% / 19時55%**（各400回）。
飲食84件には写真がほとんど無く、静けさ重みが昼に飲食を選びやすいのでこの差が出ます。

## 混雑は推定だと書く

実測なのは**広域の人出（1kmメッシュ）だけ**です。地点ごとに出している0〜100は、
時間帯の形と集客力を掛けた推定。数字を出しているところには全部そう書いてあります。

| どこ | どう出るか |
|---|---|
| 地図の凡例 | `CROWD, ESTIMATED` / `混雑の予想` |
| ランドマークの詳細 | `~64%` と大きく出し、下に `of peak · estimate` |
| 見立て | 「混雑していそう」「空いていそう」。断定しない |
| 空く時刻 | 「16時ごろから空きはじめる見込み」 |
| ヒント | 「ピーク比 およそ64%（予想）」 |

**リザルトに「すいてた%」は出しません。**推定から引き算した数字を散歩の成果として
出すのは言い過ぎなので落としました。分散ポイント自体は印の判定には残っています。

## 重みの効き

抽選は argmax ではなく重みつきランダム。**内部で重くしている項は3つ**です。

```
重み = 帯の適合 × 静けさ(100−混雑)^2.2 × 外向き(0.22+0.78×(1−人出)) × 推しエリア
帯の外・寄った場所・気分の外・閉まっている種類は、掛けずに 0 で落とす
```

| 項 | 効き（上野・平日14時） |
|---|---|
| 推しエリア（谷中900m ×2.4） | 谷中が引かれる率 **19.1% → 36.2%** |
| 外向き | 帯に入る候補134件の人出は単純平均 0.653、**重みで平均すると 0.525** |
| 静けさ ^2.2 | 混雑45の場所は混雑0の場所の 0.27倍 |

2,000回引いて **帯（15±7分）の外は0件、三択600回で重複0**。
ウェブ版で同じ条件を測ると 谷中35.9% / 帯の外0件 / 重複0 で、乱数のぶれの内側に収まります。

## 言語

**英語が主で、日本語は表紙の切り替えで出ます。**文言は `WalkStore.t(en, ja)` の1か所を
通します。辞書ファイルは作っていません。画面と文言が離れると、どちらかだけ直る事故が
必ず起きるので、書いてある場所に両方置いてあります。

印だけは `SozoroCore` の側にあるので、`Reward.title(_:)` / `condition(_:)` で持っています。
ウェブ版が `ja` / `cja` を持っているのと同じ形です。

切り替えは表紙にしかありません。歩いている途中では変えられません。

## 向こうまで抜ける — 方角をえらぶ

`Begin` を押すと、まず**どの方角へ抜けるか**を選ぶ画面に入ります。ウェブ版の `#dir` と同じで、
方角・駅・分・区間数だけを並べ、**途中に寄る場所は伏せたまま**。決められないときのために
「まかせる」も置いてあります。歩いて手ごろな駅（1300〜3800m、方角から±26°）が
無い向きは、そもそも並びません。上野からだと6方向出ます。

選んだ時点で道筋が決まるので、**途中で「まだ続けるか」は聞きません。**着いたら電車で帰れます。

## ネイティブにする理由

ウェブ版で踏んだ不具合の大半が、CSSとDOMの事故でした。地図が寄ると荒い（合成レイヤーの
ラスタを引き伸ばしていた）、到着画面が潰れる（flexの縮み）、シートがはみ出す、
選択が見えない（未定義のCSS変数）、針が北をまたぐと逆回りする。**SwiftUI には無い種類の問題です。**

もっと効くのが位置情報と方位です。

```
ウェブ    navigator.geolocation + DeviceOrientationEvent
          iOSは許可を毎回、Androidはalphaを反転、屋内の初回測位が数km飛ぶ
ネイティブ CLLocationManager の trueHeading
          許可は一度、精度も更新頻度も桁違い、バックグラウンドも取れる
```

このアプリはコンパスが本体なので、ここが安定するのは大きい。
地図を MapKit にすれば、ベースマップの SVG 71KB と投影のコードと生成スクリプトが丸ごと消えます。

## ウェブ版から持ってきたもの

**アイコンは SF Symbols に置き換えていません。** ウェブ版の `<symbol>` 26種から
SVG のパスを抜き出して同梱し、`SVGPath` が `M L H V C S A Z` を読んで
`UIBezierPath` に起こします。線の太さ 1.7 も、24×24 の座標系も同じです。
別のアイコンに替えると、それだけで別のアプリの顔になるので。

**文字盤も 300×300 の座標系のまま組んで、最後に縮めています。**外輪142・内輪112・
点線86・四方の目盛り・斜め45度の印まで、ウェブ版の SVG と同じ数字です。
バラバラに配置すると必ずズレるので、組んでから縮める順にしてあります。

**基準地点21件**（浅草寺・スカイツリー・アメ横・上野公園……）をアイコンで地図に置き、
叩くと詳細が出ます。いまの混み具合、一日のかたちのグラフ、いつ空きはじめるか、
そして「3層のうち実測はどれか」まで。ウェブ版の detail シートと同じ中身です。

**混雑はにじみで出します。**基準地点に色の丸をぼかして重ね、掛け算で合成する。
点だけだと「どのあたりが混んでいるか」が読めません。集客力が大きいほど広くにじみ、
混んでいるほど濃くなります。マーカー自体はウェブ版と同じ**白い丸に線画、右上に混み具合の点**。

**地図は遊べる範囲のちょい外までで止めてあります**（9km四方、寄り引きも900m〜14km）。
世界地図まで引けると迷子になるので。

## 三択の一行

ウェブ版は3文を6,052件で使い回していて、**3枚が同じ顔になっていました。**
分類ごとに書き分けて **69本**にしてあります（そば8・ラーメン8・すし7・うなぎ5・
とんかつ3・お好み焼き4・寺10・神社4・史跡6・公園3……）。日本語も同数。

同じ場所には毎回同じ文が当たり（引き直すたびに変わると嘘くさい）、
**同じ回の3枚で重なったときだけずらします。**200回引いて重なり0をテストで縛ってあります。

サムネの色も地点ごとに振ってあります。食は暖色、それ以外は寒色の帯の中で、
名前から色相と明度を散らす。**同じ気分の3枚が同じ色にならない**ようにするためです。

分類は英語で見ている人には言い換えます（`飲食店営業（そば）` → `Soba house`、
`文化財のある寺社` → `Temple or shrine`）。ヒントの「なにがある」もこれを使うので、
英語モードで日本語が出ることはありません。

## 地図の端と、詳細の出し方

**凡例と縮尺を端に置いてあります。**色で塗っておいて何色が混んでいるのか言わないのは、
読めない図になるので。ウェブ版の map-foot と同じ並びで、縮尺は
50/100/200/500/1000/2000/5000 の刻みから地図の倍率に合うものを選びます。

**詳細は画面の中央に、フォームより前に出します。**上に出していたときは
閉じるボタンに指が届きませんでした。背景を暗くして、外を叩いても閉じられます。

絵は**アイコンの種類ごとに8通り**（五重塔・塔・寺・博物館・公園・駅・工房・商店街）。
ウェブ版は浅草寺の一枚絵でしたが、基準地点が21あるので描き分けています。
**人影は混み具合で増えます**（0〜14人）。数字より先に、絵で伝わるように。

## エリア外の扱い

行き先の母集団が台東区と荒川区に寄っているので、**区の外から開いた人には
そう伝えます。**地図の帯に「いちばん近い基準地点まで何mのどっち」を出し、
Begin は押せなくして理由を書く。黙って押せないボタンが、いちばんよくない。

区の輪郭はウェブ版の描画用ポリゴンを緯度経度に直したもので、交差数で内外を決めます。
9地点で判定を確かめるテストが入っています（上野・浅草・谷中・蔵前・根岸は中、
南千住・東京駅・押上・日暮里は外）。

## 到着画面
